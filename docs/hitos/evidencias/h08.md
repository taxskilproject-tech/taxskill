### Recuperación y descarga

Último ensayo: dos proyectos Docker aislados, uno de fuente y otro de restauración. Copia: 459 ms; recuperación y regresión del destino: 60.990 ms. Total del comando: 130,14 s, incluyendo preparación/retirada de ambos proyectos. **Un objeto de 883 bytes**, suficiente para demostrar bytes reales; no acredita rendimiento para el volumen productivo.

Se verificaron:

- Descarga de una versión confirmada por cliente autorizado y hash igual al original.
- Denegación de firmar directamente una URL arbitraria de una hora desde Storage SDK.
- Retirada de la concesión que impide una descarga nueva.
- URL anterior de 60 segundos efectivamente caducada después de preparar/restaurar el destino.
- Al menos una sesión activa dentro del snapshot revocada durante recuperación; su JWT anterior no lee estudios del destino.
- Cero jobs en el destino antes del login nuevo y ningún envío externo histórico.
- 64 migraciones coincidentes y las 13 huellas de reglas, obligaciones, versiones, revisiones, avisos, laboral y auditoría conservadas.

Las primeras ejecuciones detectaron dependencias Edge ausentes en el proyecto auxiliar y falta de URL pública local. Se corrigió el scaffold sin tocar el proveedor real. La regresión H03 inicial detectó que el reinicio local había retirado variables de Edge; se restableció `functions serve` con el archivo local ignorado y la reejecución de 59 casos pasó. Una copia inicial de la base principal rechazó objetos ausentes de las fixtures de capacidad H07: se conserva ese rechazo correcto y la historia, y se usa una fuente aislada con un PDF real. No se borraron metadatos para ocultar el fallo.

RPO/RTO/retención productivos siguen por validar con el destino independiente y el volumen real. No se ejecutó `backup:cloud`, no se configuró S3, ni se enviaron mensajes a Evolution.
