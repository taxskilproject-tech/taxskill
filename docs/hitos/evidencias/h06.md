## 1. Alcance entregado

Once migraciones incrementales `20261017000900`–`20261017001900`. Bandeja sobre las obligaciones originales, adicionales únicas/recurrentes de empresa o internas, revisión de archivos compartida, reasignación, indicadores separados, centro de avisos personal y contador Realtime. Se completan las 29 tablas con digests e intentos, sin crear una entidad paralela de tareas o lotes.

La integración incorpora dispatcher Edge/Cron, payload 1.0 congelado, claim durable anterior al proveedor, workflow n8n importable y endpoint de receipts con secreto independiente. Incluye seguimiento administrativo de contacto/entrega/intentos y conciliación de evidencia guardada.

Todos los usuarios, empresas, archivos, teléfonos y mensajes de prueba se crearon exclusivamente en **Supabase Docker TaxSkill 54331**, n8n Docker 5679 y proveedor ficticio 5680. No se enviaron mensajes WhatsApp reales. Los scripts rechazan destinos remotos antes de crear clientes o leer fixtures.

## 3. Matriz de integración y fallos

| Caso | Evidencia |
|---|---|
| Misma identidad e indicadores | UUID de inbox igual a obligación; cliente no recibe interna; documental/adicional con denominadores independientes. |
| Adicional incompleta | Sin posiciones o sin tamaño explícito se rechaza; revisión obligatoria. Repetición de petición devuelve la misma obligación. |
| Recurrencia | Regla adicional usa H04 y segunda generación no duplica. Snapshot anterior permanece igual al cambiar responsabilidad. |
| Plazo y corrección | Cinco umbrales una vez por ciclo; entrega recibida se retira del atraso aun pendiente de aprobación. Observación se vincula al nuevo ciclo; evento H03 anterior se resuelve sin modificar historia. |
| Responsabilidad retirada | Incidencia visible; sin elementos para antiguo responsable. Reasignar a elegible resuelve incidencia y avisa. |
| Lectura | Solo destinatario marca aviso propio; no cambia disposición de obligación. |
| 429 + 500 | Exactamente tres reservas HTTP, mismo batch y hash de payload; una llamada al proveedor. Pausas/timeout del dispatcher aplicados. |
| Reinicio n8n · CA21 | Reinicio real de `tax-skill-h06-n8n`; replay recupera el claim PostgreSQL y evidencia previa. El contador del proveedor continúa en uno. |
| Respuesta perdida | Proxy local procesa workflow y pierde respuesta; repetición conserva delivery y no repite proveedor. |
| Lote de varios destinatarios | Dos digests comparten batch; cada uno tiene delivery y resultado propios, una llamada al proveedor por destinatario. Se prueba el enlace de ítems del workflow. |
| Timeout del proveedor · CA22 | Se guarda unknown. El stub tiene evidencia independiente de entrega; solo un receipt posterior respaldado por esa evidencia concilia a delivered. |
| Fallo del proveedor · CA22 | HTTP aceptado, estado failed y delivered_at NULL; no se fabrica entrega. |
| Timeout HTTP y límite | Timeout, 429 y 500 consumen tres intentos; proveedor no fue llamado. Otra ejecución no excede tres. |
| Callback falso/repetido/desordenado | Sin secreto: 401; cuerpo inválido: 422; pruebas de límite UTF-8: 413. Replay idéntico idempotente; conflicto de contenido rechazado; sent antiguo no degrada delivered. |
| CA20 | Sin contacto no crea envío; aviso administrativo conservado. Corrección recibida excluye observación. Pérdida de permiso elimina elementos. Sin elementos no hay digest vacío. |
| Cambio de día | Pending no aceptado caduca sin modificar payload; unknown no caduca ni libera su observación para duplicación. Atraso abierto puede recordarse otro día. |
| Privacidad | Contrato estricto rechaza salario, diagnóstico, archivos, detalle de observación y URL firmada. Payload real del stub sin descripción privada; logs solo IDs, conteos y evidencia mínima. |

## 6. Cloud y continuidad

Se publicaron las once migraciones SQL H06 mediante `supabase db push --linked --yes`, **sin seeds ni fixtures**. Cloud `gzwrqvqofcrdjvzoblaz` queda con **47 migraciones y 29 tablas públicas**; dry-run posterior sin pendientes y lint sin errores. Las doce huellas históricas comparadas antes/después coinciden, sin excluir campos por H06. Registros ignorados en `test-results/cloud/h06-*`.

No se activó `h06-notifications-dispatch` en Cloud, ni se configuró un proveedor real ni se enviaron mensajes desde ese entorno. La aplicación local continúa apuntando a Docker. El despliegue de esquema no acredita configuración productiva de Edge/n8n/WhatsApp ni una publicación Vercel.

H08 conserva RLS de datos/Storage, autorización privada Realtime, proveedor/remitente/plantillas, dominio, secretos, monitoreo, respaldos y piloto. La implementación verificada permite continuar técnicamente con [H07](../h07-supervision-reportes.md); la aceptación formal sigue perteneciendo al equipo/usuario.
